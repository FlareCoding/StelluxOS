## 1. Mission & key decisions

- **Goal:** cold-boot the RTX 3080 (GA102, PCI `10de:2216` @ `0000:0b:00.0`) from StelluxOS and draw a pixel at 2560×1440@60 on the DP panel (RM `displayId 0x800` / head 3 / SOR 1 / DP_B), then 144 Hz.
- **Core idea:** we do **not** reimplement the resource manager. `gsp_ga10x.bin` (the GSP-RM firmware) runs the real RM on the GPU's GSP. StelluxOS implements only the **host-side client**: boot the GSP, set up an RPC channel, and drive it. Firmware blobs reused verbatim; the GPU BROM does all crypto.
- **Decisions (locked):**
  - **Greenfield** reimplementation (not the old branch's code).
  - Target **535.183.01** (openrm) — matches the golden traces and the host firmware blob.
  - **x86-only experimental spike** under `kernel/drivers/gpu/nvidia/` (the dual-arch rule is intentionally set aside for this vertical; the code still compiles as a no-op on aarch64).
  - **IOMMU off / identity map** assumed → device DMA uses raw physical addrs (`dma_addr == phys`). Validated: FWSEC DMA worked from phys `0x829520000` (>32 GB), and the rtl8168 NIC DMAs fine.

## 4. StelluxOS integration facts (the OS-specific glue)

- **Privilege model (dynpriv):** wrap privileged hardware ops in `RUN_ELEVATED(...)` (config R/W, `vmm::*`, `mmio` on kernel device pages, `heap::k*`). `RUN_ELEVATED` is a no-op if already elevated. `stlx_init` runs privileged, but wrapping is the robust pattern. **Old-branch lesson:** if the driver ever runs in a *deprivileged* task, DMA pages it touches need `PAGE_USER`, and you cannot deref `.rodata` string literals from deprivileged code — cache values during `attach()`.
- **APIs:** `pci::device` (`enable()`=IO+MEM, `enable_bus_mastering()`=BME, `config_read*/write*`, `get_bar`, `vendor_id/device_id`), `pci::device_count/get_device`. `vmm::map_device(phys,size,PAGE_READ|PAGE_WRITE|PAGE_DEVICE,base,va)` (uncached MMIO), `vmm::alloc_contiguous(pages,zone,flags,ALLOC_ZERO,kva::tag::generic,va,phys)`. `mmio::read8/16/32`, `write32` (no 64-bit helper). `clock::now_ns()` + `delay::us/ns`. `fs::open/read/seek/stat/close` (works from boot context!). `heap::kzalloc/kfree`. `barrier::dma_write`=sfence, `dma_full`=mfence.
- **64-bit BARs:** `pci::parse_bars` stores a 64-bit BAR at the low PCI slot and marks the high slot `NONE`. **BAR0 on GA102 is 32-bit** (reads back `type=2`), so it occupies slot 0; BAR1/BAR3 (64-bit) are at slots **1** and **3** (NOT 2/4). `BAR_REGS=0, BAR_FB=1, BAR_INST=3`.
- **Logging:** `log::info/warn/error(fmt, ...)`, printf-style. **LP64: use `%lx`/`%lu` for 64-bit (uintptr_t/uint64_t/size_t), `%x`/`%u`/`%02x` for 32-bit. NO `%llx`.** Serial is slow (~115200 baud); a ~95-char line ≈ 8 ms (this is why a "0 us"→"9181 us" timing was just serial latency, not real wait).
- **Build:**
  - `make kernel ARCH=x86_64` then `make image ARCH=x86_64` → `images/stellux-x86_64.img`. Also build `ARCH=aarch64` (must stay clean — the driver compiles there as a no-op).
  - The disk image was enlarged **64 MB → 256 MB** (the 38 MB firmware) in `Makefile` (`IMAGE_SIZE_MB=256`, `IMAGE_PART_END=524254`) and `scripts/flash-x86.sh`.
  - Firmware is staged at `initrd/firmware/nvidia/535.183.01/gsp_ga10x.bin` → appears at `/firmware/nvidia/535.183.01/gsp_ga10x.bin` in ramfs (the cpio bundles all of `initrd/`).
- **Dev/test loop:** build image → user flashes + boots on the **physical box** (the RTX 3080 is in this machine, `0b:00.0`) → kernel serial logs stream to a Raspberry Pi → user pastes `screenlog.0` back → we diff `nvidia:`/register output against the golden `boot-trace.txt`. **Print generously.**

## 5. GA102 hardware facts (verified on this card)

- **Identity:** `NV_PMC_BOOT_0 (0x0) = 0xb72000a1` → chipset `0x172` (arch `0x17` Ampere, impl `0x2`), rev a1. Fields: ARCH 28:24, IMPL 23:20, MAJOR 7:4, MINOR 3:0 (`nv_ref.h`).
- **BARs:** BAR0 regs `0xfb000000` 16 MB **uncached**; BAR1 VRAM `0xd0000000` 256 MB prefetch; BAR3 inst `0xe0000000` 32 MB.
- **GFW devinit gate** (`kern_gpu_tu102.c:_gpuIsGfwBootCompleted`): (1) `NV_PGC6_AON_SECURE_SCRATCH_GROUP_05_PRIV_LEVEL_MASK (0x118128)` bit0 `READ_PROTECTION_LEVEL0` must be ENABLE; (2) `GROUP_05_0_GFW_BOOT = GROUP_05(0) (0x118234)` low byte `PROGRESS` == `0xFF` COMPLETED.
- **Usable FB size:** `NV_USABLE_FB_SIZE_IN_MB = NV_PGC6_AON_SECURE_SCRATCH_GROUP_42 (0x1183a4)`, value in MiB (= 10240). `fbSize = mib << 20`.
- **VBIOS PROM:** `NV_PROM_DATA(i) = 0x300000 + i` (BAR0). Extract per `kgspExtractVbiosFromRom_TU102`: skip IFR (`NV_PBUS_IFR_FMT_FIXED0/1/2` @ 0/4/8, sig `0x4947564E`; v3 → flashStatus → ROM dir `"RFRD"=0x44524652`), then walk PCI exp-ROM chain (sig `0xaa55`; PCIR `"PCIR"/"NPDS"/"RGIS"` @ ptr `0x18`; NPDE `"NPDE"=0x4544504E`; 512-B blocks; code types base `0x00`, ext `0xE0`). `expansionRomOffset = extRomOffset - baseRomSize` = **`0x16a00`**; total = 563200.
- **FWSEC parse** (`kernel_gsp_fwsec.c`): BIT header (`id 0xB8FF`, sig `"BIT\0"=0x00544942`, checksum) → walk tokens (6 B each) → `BIT_TOKEN_FALCON_DATA (0x70)` → `FalconUcodeTablePtr` → ucode table → entries → FWSEC (`APPID_FWSEC_PROD 0x85` / `FIRMWARE_SEC_LIC 0x05`). VBIOS version from `BIT_TOKEN_BIOSDATA (0x42)` BINVER.
  - **⚠ CRITICAL OFFSET RULE:** the ucode table, its entries, and the descriptor are addressed at **`expansionRomOffset + ptr`**; the BIT header and token `DataPtr`s are **absolute**. This is the exact "virtual vs absolute" bug the old branch fought. (`kernel_gsp_fwsec.c:549/580/603/645`.)
- **FALCON_UCODE_DESC_V3** (44 B, `"9d1w2b2w"`): `StoredSize, PKCDataOffset, InterfaceOffset, IMEMPhysBase, IMEMLoadSize, IMEMVirtBase, DMEMPhysBase, DMEMLoadSize, EngineIdMask(u16), UcodeId(u8), SignatureCount(u8), SignatureVersions(u16)`. On this card: IMEM 57856, DMEM 2048, Stored 59904, PKCDataOffset `0x5a4`, InterfaceOffset `0x1c`, EngineIdMask `0x400`, UcodeId 9, sigCount 3, sigVersions `0x7`. `descSize 1196 = 44 + 3×384`.
- **FWSEC ucode bytes:** at `VBIOS[descOffset + descSize]`, length `ALIGN_UP(StoredSize,256)=59904`; code `[0,57856)`, data `[57856,+2048)`. The 3 RSA-3K sigs (`384` B each) are at `VBIOS[descOffset + 44]`.

### Falcon engine (the reusable DMA-load-and-go) — GSP Falcon
- **Bases:** `registerBase = NV_PGSP = 0x110000`; `riscvRegisterBase = NV_FALCON2_GSP_BASE = 0x111000` (BROM + BCR); `fbifBase = NV_PGSP_FBIF_BASE = 0x110600`.
- **Falcon regs (off from registerBase):** `MAILBOX0 0x40`, `MAILBOX1 0x44`, `OS 0x80`, `RM 0x84`, `HWCFG2 0xf4`, `CPUCTL 0x100`, `BOOTVEC 0x104`, `DMACTL 0x10c`, `DMATRFBASE 0x110`, `DMATRFMOFFS 0x114`, `DMATRFCMD 0x118`, `DMATRFFBOFFS 0x11c`, `DMATRFBASE1 0x128`, `CPUCTL_ALIAS 0x130`, `ENGINE 0x3c0` (reset).
- **Fields:** `CPUCTL.STARTCPU` bit1, `.HALTED` bit4, `.ALIAS_EN` bit6; `HWCFG2.RISCV` bit10, `.MEM_SCRUBBING` bit12 (0=done), `.RESET_READY` bit31; `DMATRFCMD.IDLE` bit1 (1=done), `SIZE_256B = 6<<8`, `IMEM = 1<<4`, `SEC = 1<<2`. IMEM cmd `0x614`, DMEM cmd `0x600`. Block size 256.
- **BROM regs (off from riscvRegisterBase):** `MOD_SEL 0x180` (`ALGO_RSA3K=1`), `BROM_CURR_UCODE_ID 0x198`, `BROM_ENGIDMASK 0x19c`, `BROM_PARAADDR(0) 0x210`. **BCR_CTRL `0x668`** (`CORE_SELECT` bit4 0=FALCON, `VALID` bit0 HW-set, `BRFETCH` bit8). `RISCV_CPUCTL 0x388` (`ACTIVE_STAT` bit7).
- **FBIF regs (off from fbifBase):** `TRANSCFG(0) 0x000` (`TARGET` 1:0 `COHERENT_SYSMEM=1`, `MEM_TYPE` bit2 `PHYSICAL=1`), `CTL 0x024` (`ALLOW_PHYS_NO_CTX` bit7).
- **⚠ RESET (the run-#8 bug → run-#9 fix):** the open driver's `kflcnReset` does handshakes, not just writes. Required sequence (×2 for disable+enable), then `FALCON_RM=chipId`:
  1. `PreResetWait`: poll `HWCFG2.RESET_READY`.
  2. engine reset: `ENGINE=1` then `ENGINE=0`.
  3. `WaitForResetToFinish`: poll `HWCFG2.MEM_SCRUBBING`→done.
  4. **`SwitchToFalcon`: write `BCR.CORE_SELECT=FALCON (0)` and POLL `BCR.VALID==1`.** ← The GSP boots in **RISC-V** mode; FWSEC is a **Falcon** ucode. Without confirming the switch, `CPUCTL.STARTCPU` is a no-op → Falcon never halts (run #8 symptom: clean DMA, `rc=-51` no-halt).
- **HS execute** (`kgspExecuteHsFalcon_GA102`): DisableCtxReq → TRANSCFG(COHERENT_SYSMEM|PHYSICAL) → DMA IMEM (`DMATRFBASE=phys>>8`, `BASE1=hi&0x1FF`; loop MOFFS/FBOFFS/CMD=`0x614`, poll IDLE; SEC=1) → DMA DMEM (CMD=`0x600`) → BROM (`PARAADDR=PKCDataOffset`, `ENGIDMASK`, `CURR_UCODE_ID`, `MOD_SEL=RSA3K`) → `BOOTVEC=imemVa` → StartCpu (`CPUCTL=0x2`, or `CPUCTL_ALIAS` if `ALIAS_EN`) → poll `CPUCTL.HALTED`.

### FWSEC-FRTS specifics
- **FB layout / frtsOffset** (`kgspCalculateFbLayout_TU102`, FRTS slice): `vgaWorkspace = fbSize - 0x20000`; `wprEnd = ALIGN_DOWN(vgaWorkspace - wprEndMargin, 0x20000)`; **`frtsOffset = wprEnd - frtsSize(0x100000)` = `0x27fee0000`**. (MMU-lock and `wprEndMargin` are 0/absent on this consumer GA102 — confirmed by `WPR2_LO` matching exactly.)
- **FRTS command** (`FWSECLIC_FRTS_CMD`, 44 B = `readVbiosDesc(24)` + `frtsRegionDesc(20)`): `readVbiosDesc{version=1,size=24,gfwImageOffset=0,gfwImageSize=0,flags=2}`; `frtsRegionDesc{version=1,size=20,frtsRegionOffset4K=frtsOffset>>12,frtsRegionSize=0x100,frtsRegionMediaType=FB=2}`. Patched into the FWSEC **DMEM** via the interface walk: header @ `InterfaceOffset(0x1c)` (`{version,headerSize,entrySize,entryCount}` 4 B) → entries (`{id(u32),dmemOffset(u32)}` 8 B) → find `id==DMEMMAPPER(0x4)` → in the `DMEM_MAPPER_V3` struct set `init_cmd(@+44)=0x15` and copy the cmd to `cmd_in_buffer_offset(@+8)`.
- **Signature selection (fuse bit-walk, NOT `fls`):** `index=ucodeId-1`; `fuseVal=RD32(NV_FUSE_OPT_FPF_GSP_UCODE1_VERSION(0x8241c0) + 4*index)`; `fuseVer = HIGHESTBITIDX(fuseVal)+1` (fuse `0x3`→fuseVer 2); `ucodeVersionVal = 1<<fuseVer`; walk `sigVersions`: `while((uvv & hsv & 1)==0){ sigOffset += (hsv&1)*384; hsv>>=1; uvv>>=1; }`. Copy the selected 384-B sig into DMEM at `PKCDataOffset(0x5a4)`. (SEC2 Booter uses a DIFFERENT rule: `sigIndex = numSigs-1-fuseVer` — see `kernel_gsp_booter.c:146-165`.)
- **WPR2 verify:** `NV_PBUS_VBIOS_SCRATCH(0x0E)=0x1438` bits 31:16 `FRTS_ERR`==0; `WPR2_ADDR_HI(0x1fa828)>>4 != 0`; `WPR2_ADDR_LO(0x1fa824)>>4 == frtsOffset>>12`. Observed: `WPR2_HI=0x027ffc00`, `WPR2_LO=0x027fee00`.

### radix3 over the GSP-RM image (`_kgspCreateRadix3`, `kernel_gsp.c:3470-3560`)
- `LIBOS_MEMORY_REGION_RADIX_PAGE_SIZE=4096`, LOG2=12; 512 entries/4K page; entries are **raw byte phys** (`RmPhysAddr`, what `memdescGetPhysAddrs` writes). 4-level working array `radix3[0..3]` (0=root, 3=data). `nPages[3]=ceil(size/4K)`, `nPages[i-1]=((nPages[i]-1)>>9)+1`; **root must be 1 page**. For 38 MB `.fwimage` (9312 pages): `nPages=1/1/19/9312`, page table = 21 pages.
- **StelluxOS simplification (valid):** the open driver backs the image with non-contiguous pages and fills PTEs via `memdescGetPhysAddrs`; StelluxOS has **no per-page phys query**, but its buddy allocator gives large contiguous blocks (≤1 GiB), so we back `.fwimage` with one contiguous DMA buffer → PDE/PTE fills are pure arithmetic (`l1[j]=tphys+off2+j·4K`, `leaf[k]=dphys+k·4K`). The GSP only walks the table; contiguity is invisible to it. Verified run #10.

### GSP-RM boot ucode (SK+BL) — `nv_bootimg`, Stage 7a
- **NOT a firmware file.** In the open driver it is compressed **bindata**: `kgspGetGspRmBootUcodeStorage_GA102` → archive `GspRmBoot_GA102`, storages `ucode_image_prod` / `ucode_desc_prod` (prod, since `kgspIsDebugModeEnabled=false` on retail). Source: `generated/g_bindata_kgspGetBinArchiveGspRmBoot_GA102.c`.
- **Compression = raw DEFLATE (RFC 1951, no zlib/gzip wrapper).** Confirmed from `utilGzIterator` (`src/nvidia/src/lib/zlib/inflate.c`): reads BFINAL bit + 2-bit BTYPE directly. Offline decode = `zlib.decompress(data, wbits=-15)`. Extractor: `scripts/extract-nv-bindata.py` (verifies decompressed size == declared `DATA SIZE`).
- **Sizes:** image `17934 → 24576 B` (`= gspRmBootUcodeSize`), desc `42 → 84 B` (`= RM_RISCV_UCODE_DESC`). Staged at `initrd/firmware/nvidia/535.183.01/gsp_ga10x_boot_image.bin` + `gsp_ga10x_boot_desc.bin`.
- **`RM_RISCV_UCODE_DESC`** (`rmRiscvUcode.h`, 21×u32): GA102 values — `version=5`, `bIsMonitorEnabled=1`, `manifest@0x0 sz0x800`, `monitorData@0x800 sz0x1000`, `monitorCode@0x1800 sz0x2900`, `bootloader@0x5000 sz0x880`, `blParam@0x5880 sz0x10`, `fbReservedSize=0x6000`; `riscvElf*=0`, `swbrom*=0`, `bSignedAsCode=0`. **WprMeta consumes `monitorCodeOffset(0x1800)`, `monitorDataOffset(0x800)`, `manifestOffset(0x0)`** (`kgspCalculateFbLayout_TU102:616-618`).
- **Same pattern will stage the SEC2 Booter Load/Unload** (`generated/g_bindata_kgspGetBinArchiveBooterLoadUcode_GA102.c`, `...BooterUnloadUcode_GA102.c`) for Stage 9.

### FB layout + GspFwWprMeta (256 B) — `nv_wprmeta`, Stage 7b
- `kgspCalculateFbLayout_TU102` (`kernel_gsp_tu102.c:509-666`), top-down. `GspFwWprMeta` is a flat 256-byte ABI struct (`gsp_fw_wpr_meta.h`; `ct_assert(sizeof==256)`, mirrored with `static_assert`). Magic `0xdc3aae21371a60b3`, revision 1.
- **GA102 computed layout (fbSize=10240 MiB=`0x280000000`):** `vgaWorkspaceOffset=0x27ffe0000` (`fbSize-0x20000`), `gspFwWprEnd=0x27ffe0000`, `frtsOffset=0x27fee0000` (**==carved WPR2_LO, the self-consistency oracle**), `bootBinOffset=0x27feda000`, `gspFwOffset(ELF)=0x27da70000`, `gspFwHeapOffset=0x275d00000` (heap `0x7d00000`=125 MiB), `gspFwWprStart=0x275c00000`, `nonWprHeapOffset=gspFwRsvdStart=0x275b00000` (1 MiB).

### RPC plane — `nv_msgq` + `nv_rpc`, Stage 8
- **Shared block** (`GspMsgQueuesInit`, CACHED, contiguous): `[ page table (0x1000) | cmd ring (0x40000) | status ring (0x40000) ] = 0x81000` (129 pages). - **⚠ StelluxOS gotcha:** `memcpy`/`memset` live in `namespace string` (not global C ABI). A large `out = T{}` struct value-assignment makes the compiler emit a global `memcpy` → **undefined-symbol link error**. Use `string::memset(&x,0,sizeof x)` and write byte-copy loops with **volatile** pointers (prevents loop-idiom → `memcpy`). Applies to all driver code.
- **⚠ Build gotcha (no header-dep tracking):** the kernel build only recompiles a `.cpp` when *that file* changes, not when an included `.h` changes. After editing a header (esp. a function-signature change like `nv_falcon.h`), **`touch` the dependent `.cpp`s** (e.g. `touch kernel/drivers/gpu/nvidia/*.cpp`) or you'll get stale-`.o` undefined-symbol link errors. Additive-only header edits (new constants) are safe for unchanged `.o`s.

### Stage 10d — ROOT CAUSE: REG_POLL timeout==0 means GPU_TIMEOUT_DEFAULT, not "no wait" [run #18 -> fix]
- **Run #18 made the bug obvious:** failed at `seq[0]` (the very first opcode) = `REG_POLL(MAILBOX0=0x110040, mask=0x80000000)` with **`timeoutMs=0`**, `got=0x502`. My REG_POLL computed `to_ns = a[3]*1e6 = 0` -> read once, instant timeout. Run #17 only *passed* seq[0] by winning a timing race; the added seq logging in #18 shifted timing and lost it.
- **DEFINITIVE source evidence:** `GPU_TIMEOUT_DEFAULT == 0` (`gpu_timeout.h:40`); `timeoutSet()` maps `timeoutUs == GPU_TIMEOUT_DEFAULT` to `pTD->defaultus` (`gpu_timeout.c:214-216`), i.e. the platform default `osGetTimeoutParams => 4 s` (graphics mode). So the GSP's `timeout=0` polls are meant to wait the **default ~4 s**, not zero. Non-zero values are microseconds (`timeoutSet:231 timeoutNs = timeoutUs*1000`; the rmgspseq.h ":52 in MS" comment is stale/wrong).
- **This single bug caused BOTH prior sequencer failures:** run #17 `DMATRFCMD` IDLE poll (`got=0x614`) was the DMA still in-flight on the *first* read — my zero-timeout bailed before the ~3 us DMA finished (the DMA was fine, not hung); run #18 the MAILBOX0 handshake race.
- **Fix (`nv_seq` REG_POLL):** `to_ns = (a[3]==0) ? 4 s : a[3]*1000 (us->ns)`. Now matches RM: the MAILBOX0 handshake waits for the GSP to set bit31, and each DMATRFCMD poll waits for the 256B DMA to go IDLE. Build clean both arches + image. -> run #19.
- **Lesson:** NVIDIA RM "0 == default timeout" is a pervasive convention; any ported poll/timeout that takes an RM timeout value must treat 0 as the default, not zero.

### Stage 10e — run #19: per-opcode logging delay breaks the MAILBOX0 handshake

## 7. Working method (do this for every new register/sequence)

1. Find the authoritative logic in `~/dev/gpu-repro/open-gpu-kernel-modules` (535.183.01). Note `file:line`.
2. Resolve exact offsets/fields from `src/common/inc/swref/published/ampere/ga102/dev_*.h` (and `turing/tu102/` for shared defs).
3. Cross-check the actual on-hardware writes in `~/dev/gpu-repro/traces/20260530-123650-open-capture/boot-trace.txt` (`RVGREG wr off=0x... val=0x...`).
4. Port it into the matching `nv_*` module with **heavy `log::info` at every step / register group** (the serial loop is our debugger).
5. Build both arches + image; hand off for a hardware run; diff the serial output against the trace; iterate.
6. If a value is missing from the traces, add an `RVG*` trace point to the open driver and re-run `~/dev/gpu-repro/capture_open.sh`.
